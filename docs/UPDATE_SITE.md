## Сначала главное: сайт больше не на Netlify

Переезд, описанный в `YANDEX_CLOUD_DEPLOY.md`, уже выполнен. Что показала проверка:

| Что проверяли | Результат |
|---|---|
| NS-серверы домена | `ns1.yandexcloud.net`, `ns2.yandexcloud.net` — DNS-зона в Yandex Cloud |
| Куда резолвится домен | `topology.gslb.yccdn.ru` → 188.72.103.4 — Yandex Cloud CDN |
| Заголовки ответа | `Cache-Host: yccdn-khabttk-1`, `Cache-Status: HIT` — раздаёт Yandex CDN |
| Страница 404 | `Code: NoSuchKey` — формат ошибки Yandex Object Storage, значит источник CDN — бакет |

**Из этого следует:**
- **Netlify в цепочке не участвует.** Если залить файлы туда, на `oneofstudio.ru`
  не изменится ничего. Аккаунт Netlify можно просто удалить.
- **На reg.ru делать нечего.** Там домен только зарегистрирован, а управление
  DNS делегировано в Yandex Cloud. Заходить в reg.ru нужно лишь если домен
  надо продлить или сменить NS-серверы обратно.
- Обновление сайта = **залить файлы в бакет Object Storage и сбросить кэш CDN.**

## Шаг 1. Пересобрать папку `deploy/`

Если она уже собрана (в этой сессии — собрана и проверена), шаг пропускается.
Иначе, из корня проекта:

```bash
rm -rf deploy && mkdir -p deploy/assets/web/social deploy/brand_assets/web && cp *.html style.css robots.txt sitemap.xml deploy/ && cp assets/web/*.webp assets/web/*.jpg assets/web/*.mp4 deploy/assets/web/ && cp assets/web/social/* deploy/assets/web/social/ && cp brand_assets/web/logo.png brand_assets/web/favicon.* brand_assets/web/apple-touch-icon.png deploy/brand_assets/web/
```

## Шаг 2. Открыть бакет в консоли Yandex Cloud

1. Зайти на https://console.yandex.cloud под тем же Yandex ID, под которым
   делали переезд.
2. Слева выбрать сервис **Object Storage**.
3. Открыть единственный бакет в каталоге. Имя может быть любым — оно не обязано
   совпадать с доменом. Понять, что бакет тот самый, можно по содержимому:
   внутри лежат `index.html`, `style.css`, папки `assets` и `brand_assets`.

## Шаг 3. Залить изменённые файлы

1. В бакете нажать **Загрузить**.
2. Перетащить из папки `deploy/` файлы `index.html` и `style.css`. Они лягут в
   корень бакета поверх старых — консоль спросит подтверждение перезаписи,
   согласиться.
3. Отдельно перетащить папку `deploy/assets/web/social` — консоль сохранит
   вложенность, файлы должны оказаться по пути `assets/web/social/...`.
   Это 29 МБ, заливка идёт несколько минут.
4. Остальные страницы, старые картинки, `robots.txt` и `sitemap.xml` не
   менялись — заливать их не нужно.

> Альтернатива: перетащить из `deploy/` сразу `index.html`, `style.css`
> **и папку `assets` целиком** — консоль сохранит вложенность. Дольше
> (перезальются и старые видео), но ошибиться с путём невозможно.

## Шаг 4. Проверить Content-Type у новых файлов

Свойства объекта → поле «Тип контента». Обычно определяется сам по расширению,
но если стоит `application/octet-stream` — поправить вручную:

| Файл | Должно быть |
|---|---|
| любой `*.html` | `text/html` |
| `style.css` | `text/css` |
| `robots.txt` | `text/plain` |
| `sitemap.xml` | `application/xml` |
| `og-cover.jpg` | `image/jpeg` |

Если у `robots.txt` останется `octet-stream`, поисковики его просто не прочитают.

## Шаг 5. Сбросить кэш CDN — без этого изменений никто не увидит

Ответ боевого домена содержит `Cache-Status: HIT`, то есть CDN отдаёт файлы из
своего кэша и в бакет не ходит. Пока кэш не сброшен, посетители будут видеть
старую страницу ещё несколько часов.

1. В консоли открыть сервис **Cloud CDN** → ваш CDN-ресурс.
2. Вкладка **Содержимое** (или кнопка «Очистить кэш» / Purge).
3. Очистить либо всё содержимое, либо точечно указать пути:
   ```
   /
   /index.html
   /choreo.html
   /kpop.html
   /hip-hop.html
   /style.css
   /robots.txt
   /sitemap.xml
   ```
4. Сброс занимает от нескольких секунд до пары минут.

## Если что-то пошло не так

- **Сайт открылся со сломанной вёрсткой.** Значит `style.css` залился, а
  `index.html` — нет, или наоборот. Залить оба заново и снова сбросить кэш.
- **Картинки пропали.** Проверить в бакете, что пути остались
  `assets/web/hero.webp`, а не `hero.webp` — при перетаскивании папки консоль
  иногда «разворачивает» вложенность.
- **Ничего не изменилось.** Кэш CDN не сброшен (шаг 5) либо смотрите не в
  инкогнито. Проверить можно так — команда покажет дату файла на сервере:
  ```bash
  curl -sSI https://oneofstudio.ru/ | grep -i "last-modified\|cache-status"
  ```
  Если `Last-Modified` — старая дата, файл в бакете не перезаписался.
- **Откат.** Прошлые версии файлов лежат в git: `git log -- index.html`,
  затем `git show <хеш>:index.html > index.html` и залить обратно.

## Про Netlify отдельно

Если Netlify-аккаунт ещё жив, он раздаёт старую копию сайта по адресу вида
`***.netlify.app`. Это не влияет на `oneofstudio.ru`, но стоит удалить сайт
в Netlify, чтобы никто случайно не обновлял его вместо боевого и чтобы старая
версия не всплывала в поиске. Возвращаться на Netlify не нужно: его IP-адреса
блокируются в России, из-за этого переезд и делали.
